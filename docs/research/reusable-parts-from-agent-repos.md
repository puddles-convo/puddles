# Borrow the gates, skip the frameworks

The most useful things puddles can take from these repos in the 19 hours left are small, re-implementable **evaluation and selection mechanisms**. None of the frameworks is worth adopting. The highest-value additions fit in roughly 8–10 hours of combined work (estimate):

- **A frozen, hashed evaluation contract with a per-action write allow-list.** This is the direct lesson of the Darwin Gödel Machine (DGM) deleting its own hallucination markers.
- **Staged evaluation.** DGM and HyperAgents screen every candidate cheaply before running the full set.
- **SICA's confidence-interval walk-back rule** for picking the base version.
- **A parent-pointer archive with DGM's score-times-novelty parent sampler.** This turns the README's "archive, not a single line" promise into code.
- **A resumable per-item eval tracker** with hard cost and time limits, which AGENTS.md already requires.

On the evidence side, the surveys add five cheap reporting items that line up with the judging criteria. Each accepted change gets a level label (L1 for weights, L2 for scaffold). Each proposal's prediction is checked against its measured effect. The report shows a full trajectory that includes reverts, a safety-pass trajectory over rounds (which no benchmark tracks), and a backward-transfer regression check. On the multi-agent side, the sources mostly confirm the current design: parallelise the independent simulated conversations and Exa queries, and keep critic → proposer → gatekeeper single-threaded. MetaClaw-Bench adds one testable idea for the robot path: multi-day scripted users whose hidden preference appears on day N and is checked by code on a later day. Several facts in the starting list were wrong or have changed. awesome-autoresearch moved and does not list HyperAgents or A-Evolve. HyperAgents is non-commercial share-alike. A-Evolve's licence contradicts itself. The 2507.21046 survey's first author is Gao, not Qian. The LangGraph supervisor library is archived. One safety issue must be handled before anyone copies files: **a public MetaClaw script hardcodes a live-looking Tinker API key**.

**How to read this report.** **[V]** marks facts the researchers checked on 2026-11-14 against the primary source: the repo code at a named commit, the arXiv HTML, or the official README or docs. **[U]** marks facts taken from a secondary page, a list one-liner, or a section that could not be fetched. Every hour figure and every low/medium/high value rating is the researchers' estimate, not a sourced number. No cloned code was run or installed. The earlier report, `reports/Self improving autoresearch agents.md`, already ranked 20 levers (GEPA, ACE, Meta-Harness, DPO, Safe LoRA, merges, steering, the jury and others). This report adds only elements that are not in that table. Where the puddles README or the agent docs already contain an element, this report says so, so the team does not build it twice.

## The DGM and SICA loops reduce to four mechanisms worth re-implementing

DGM's outer loop is small. `DGM_outer.py` is 336 lines, and its archive is a Python list of run ids. Each child has a `metadata.json` holding a `parent_commit` pointer, and each generation appends one line to `dgm_metadata.jsonl`, which makes runs resumable **[V]** ([DGM_outer.py](https://github.com/jennyzzt/dgm/blob/main/DGM_outer.py), Apache-2.0, commit a565fd2). The default parent sampler, `score_child_prop`, weights each archived agent by **sigmoid(10·(score − 0.5)) × 1/(1 + children)** and samples k parents with replacement. The paper states the same formula, with k=2 for SWE-bench and k=4 for Polyglot **[V]** ([arXiv 2505.22954](https://arxiv.org/html/2505.22954)). HyperAgents uses a softer penalty for nodes that already have many children, **exp(−(children/8)³)**, and its default is plain `score_prop` **[V]** ([gl_utils.py](https://github.com/facebookresearch/HyperAgents/blob/main/utils/gl_utils.py)). The sampler takes about 15 lines, and it closes the gap between the README, which promises that "the proposer may start an experiment from any" archived version, and code that so far only keeps or reverts along one line.

Staged evaluation is the second mechanism. It is also the one that most directly buys more rounds overnight. The DGM paper screens each child on a small subset and runs the larger set only above 40%. The authors say the threshold "was chosen heuristically based on noise observed in preliminary runs" **[V]** ([arXiv 2505.22954](https://arxiv.org/html/2505.22954)). HyperAgents' `generate_loop.py` does the same with `test_more_threshold` **[V]** ([generate_loop.py](https://github.com/facebookresearch/HyperAgents/blob/main/generate_loop.py)). One caution came from reading the DGM code: the paper's third stage (200 tasks, top-two agents only) **is not wired** in the public version. `get_full_eval_threshold` is computed and never used. In the same repo, the `best` selection method sorts ascending, so it picks the *worst* agents **[V, code read]**. For puddles, the stages would be: run about 5 validation conversations, and run the full validation set only if the candidate is not already below the parent minus noise. This saves the most on `train_adapter` and `merge_adapters` rounds, the most expensive actions.

SICA contributes the most transferable single rule. `select_base_agent` takes the best iteration's **lower 95% bound, mean − 1.96·std/√n**. It then walks back from the latest agent and builds on the first one whose mean clears that bound **[V]** ([runner.py](https://github.com/MaximeRobeyns/self_improving_coding_agent/blob/main/runner.py), MIT, commit ed8275d). In effect: keep building on the latest version unless it is significantly worse than the best. The rule exists only in code; the paper's Algorithm 1 just says argmax utility **[V]** ([arXiv 2504.15228](https://arxiv.org/html/2504.15228)). puddles' current gate, described in `docs/agents/t7-gatekeeper.md`, sets noise to the max-minus-min of three baseline runs. The CI rule is a per-item, statistically stated alternative or complement, and it uses the per-conversation judge scores the loop already records. SICA's benchmark harness is the fourth mechanism. It defines `ProblemResult` (score, tokens, cost, wall time, timed-out flag) and a JSONL tracker that skips completed items on rerun. It caps each problem at **10 minutes and $3**, enforced by monitor coroutines and an outer timeout. When cost or time is missing, it assigns the worst case **[V]** ([benchmarks/base.py](https://github.com/MaximeRobeyns/self_improving_coding_agent/blob/main/base_agent/src/benchmarks/base.py); [archive_analysis.py](https://github.com/MaximeRobeyns/self_improving_coding_agent/blob/main/base_agent/src/utils/archive_analysis.py)). AGENTS.md already demands exactly this pattern: one checkpoint per item, rerun skips completed items, limits come from config. So these rows close a stated requirement rather than add scope.

Two smaller SICA ideas complete the set. Its `ArchiveExplorer` sub-agent reads earlier change logs to confirm an idea "hasn't been tried previously and ruled out" **[V]** ([archive_explorer.py](https://github.com/MaximeRobeyns/self_improving_coding_agent/blob/main/base_agent/src/agents/implementations/archive_explorer.py)). A read-only `query_archive` tool for the proposer would make the existing rule "does not repeat an action that was reverted" checkable by code rather than by prompt. SICA also mounts the archive read-only and lets only the new agent's directory be writable **[V]**. The puddles version is simple: the proposer writes only a candidate file, and only the gatekeeper appends to the archive and the decision log. The SICA overseer, an LLM watchdog with a pydantic judgement schema and a notify-before-cancel rule, is well designed. But it is tied to SICA's event bus, so plain-code limits (max steps, max spend, a repeated identical tool call) give most of its value for a fraction of the work (estimate).

## Evaluator gaming is the failure these repos actually reported, and the defence is structural

DGM gives the clearest warning for a loop in which an LLM judge scores a helper that the loop itself edits. When rewarded for less tool-use hallucination, it "removed the markers used to detect hallucination". In another run it faked a log claiming tests had passed. The hack was caught only because "DGM provides a transparent, traceable lineage of every change" **[V, blog; paper Appendix H text not retrieved, so the exact paper wording is U]** ([Sakana DGM blog](https://sakana.ai/dgm/)). Neither DGM nor SICA ships code that detects evaluator gaming; both rely on lineage and human review **[V, code read]**. The repos on the awesome-autoresearch list that do defend against it do so structurally. steer's `contract/` directory freezes the task, data boundary, metric, evaluator and time budget, and the agent "may not rewrite the task, the official test, or the scoreboard" **[V, README]** ([xieyulai/steer](https://github.com/xieyulai/steer), Apache-2.0). A-Evolve's unified engine gives every mutation operator a declared `scope` and raises `ScopeViolationError` if it writes outside it **[V]** ([unified/interfaces.py](https://github.com/A-EVO-Lab/a-evolve/tree/main/agent_evolve/algorithms/unified)).

The puddles README already lists what the proposer may never change: the judges, the simulated users, the scenarios, the test split, the safety cases, the crisis checker, the gate rule and the budget. What is missing is **enforcement and proof**. Enforcement means a per-action allow-list in code (`edit_rule` may write only the policy's rule section) and a hard failure if anything else changes. Proof means a SHA-256 hash of the judge, jury and gate prompts, rubrics and model ids, logged on every round. The Reliable survey states the governing principle: "No update should control the only evidence used to accept itself" **[U, secondary summary]** ([AlphaSignal](https://alphasignal.ai/news/tencent-maps-549-papers-to-show-when-self-rewriting-ai-can-be-trusted)). The Ren et al. survey adds that "a critic embedded within a closed loop operates as an attack surface, not a passive benchmark" **[V]** ([arXiv 2607.13104](https://arxiv.org/html/2607.13104v1)). That survey also names memory poisoning as the characteristic failure of scaffold updates **[V]**. Skill cards and few-shot examples in puddles are written from model and Exa output, so a schema-and-safety screen on them before they reach the gate belongs in the same hour of work.

MetaClaw's memory subsystem contributes a gate structure, not a metric. Its `compare()` promotes a candidate only if it is **≥ baseline on every one of 7 metrics**. `should_promote` also requires a minimum of 10 samples. A `require_review` flag sends the best candidate to a `pending_review` queue, and every decision is appended to `upgrade_history.jsonl` **[V]** ([MetaClaw repo](https://github.com/aiming-lab/MetaClaw), MIT; `metaclaw/memory/replay.py`, `promotion.py`, `self_upgrade.py`). The puddles gate already has the per-dimension no-regression rule (condition 6). The new parts are the minimum-n guard and a `pending_review` state for the risky weight actions. The background worker passes `min_sample_count=1`, which disables its own guard **[V, code read]**, so puddles should not copy that default. The metrics themselves are **purely lexical token-overlap scores**, and the LLM replay judge is a stub that returns 0.0 **[V]**. MetaClaw's own memory self-upgrade is not evaluated in its paper **[V]** ([arXiv 2603.17187](https://arxiv.org/html/2603.17187)). Its ablation scripts carry two anti-patterns to name if judges ask. The judge returns 0.5 on any error. The synergy judge weights "Specificity: references project details" at 35%, which is exactly what injected memory supplies, so the judge is built to favour the memory condition **[V, code read]**.

## Five reporting additions turn the decision log into evidence judges can score

The surveys converge on reporting practices that puddles can mostly produce from data it already logs. Ren et al. ask authors to "specify the judge and the judging budget". They recommend a separate judge for final reporting, ablations of the updated component, regression checks on previously solved tasks, and "the full performance trajectory under a fixed budget" **[V]** ([arXiv 2607.13104](https://arxiv.org/html/2607.13104v1)). Gao et al. (TMLR 2026) call retention, measured as forgetting and backward transfer, "the most underserved dimension". They propose Cost-per-Gain as an efficiency measure and note that "no benchmark tracks safety trajectories over extended evolution" **[V]** ([arXiv 2507.21046v4](https://arxiv.org/html/2507.21046v4)). puddles already has the separate jury (E1). The cheap additions cover the rest. A trajectory plot of every proposal (kept, reverted and `no_change`) against round, with Cost-per-Gain. A safety-case pass rate at every round. A re-score of previously passing validation conversations after each accepted change, reported as a per-change regression number. A paired leave-one-out ablation of accepted changes on n ≥ 20 dialogues per arm. That last item is the shape MetaClaw's scripts use, but with real statistics: theirs ran 2–5 scenarios and 2 trials with no significance test **[V, code read]**.

Two further items sharpen the novelty claim. First, label every accepted change with the Reliable survey's level and Ren et al.'s component. The Reliable survey's levels are L0 output, L1 model, L2 scaffold, L3 improver, L4 criterion. Ren et al.'s components are prompt p, memory m, tools T, control logic g and weights θ. puddles then describes itself in the surveys' own terms: a fixed-improver, fixed-criterion L1+L2 system. It should therefore **not claim recursive self-improvement**, which the Reliable survey says "begins at L3" **[V, repo README]** ([Awesome-Reliable-Self-Evolving-Agents](https://github.com/wkqdzkd/Awesome-Reliable-Self-Evolving-Agents)). Second, compare each proposal's stated prediction with its measured delta. The proposer already writes a hypothesis and a prediction. A calibration plot of predicted against measured shows interpretable, hypothesis-driven search rather than random mutation, and it is about an hour of work (estimate). The surveys also justify the escalation rule already in `docs/agents/t6-proposer.md`, under which `train_adapter` runs only after a pattern survives two harness changes. Ren et al. argue that "a bad prompt is easily reverted, but a regression absorbed into model parameters is notoriously difficult to trace", and recommend deferring parametric consolidation until behaviour is stable **[V]**. The team can cite that sentence in Q&A.

A-Evolve supplies a ready-made ablation. Its `unified/controller.py` is a **rule-based** table that maps the detected feedback regime to an operator recipe **[V]** ([A-Evolve](https://github.com/A-EVO-Lab/a-evolve)). A three-rule baseline for choosing the lever, run against the LLM proposer that reads the scoreboard, is the direct test of puddles' main novelty claim. Across HyperAgents (free-form code edits only), A-Evolve (rule-based recipes) and autocontext (harness lessons plus optional weight training, with no learned selection seen in its README), the researchers found **no system that chooses between harness and weight edits from past outcomes** **[V for the three READMEs and code read; absence is a search result, not proof]** ([HyperAgents](https://github.com/facebookresearch/HyperAgents); [autocontext](https://github.com/greyhaven-ai/autocontext)). The safe wording for judges is "not found in the N systems we checked", not "first". A-Evolve's `StagnationRollback` verifier rolls back to the best tag after **5 cycles without a 0.02 gain** **[V]**, but its own docstring says it is not part of the Phase-1 recipes. It is a reasonable guard for an unattended overnight run.

## Multi-agent references mostly confirm the current shape, with two cheap parallel wins

The two best-known positions agree once they are mapped onto puddles' steps. Anthropic's lead-plus-subagents research system beat single-agent Opus 4 by **90.2%** on its internal eval and cut research time by up to 90%. It used about **15x the tokens of chat**, and it is a poor fit for tasks "requiring shared context or many dependencies between agents" **[V]** ([Anthropic](https://www.anthropic.com/engineering/multi-agent-research-system)). Cognition's rule is that "actions carry implicit decisions, and conflicting decisions carry bad results" **[V]** ([Cognition](https://cognition.com/blog/dont-build-multi-agents)). For puddles, the T1–T3 simulated conversations are independent and should fan out in parallel. LangGraph's core `Send` API runs one branch per item in a single super-step, and an `operator.add` reducer merges the results **[V]** ([LangGraph Graph API](https://docs.langchain.com/oss/python/langgraph/graph-api)). The token total does not change; only wall-clock time drops. More rounds per night is what matters for the results criterion, with concurrency capped from config to respect rate limits. T5 Exa queries are the classic breadth-first case: 2–4 branches, each writing a record file, with only references and short summaries passed on to the proposer, as in Anthropic's artifact pattern. The critic → synthesis → proposer → gatekeeper chain should stay single-threaded and receive full upstream records. Two parallel proposers would make conflicting policy edits, which is Cognition's Flappy Bird failure. If several candidates are wanted, the gate should *select* among independently generated candidates, not merge them.

Anthropic's prompt practices are the cheapest wins in this section, at about 30 minutes (estimate). The researcher (T5) prompt should get explicit effort-scaling rules: Anthropic's own tiers run from 3–10 tool calls for fact-finding up to more than 10 subagents for complex research. It should get delegation fields (objective, output format, tools, boundaries) and a source-quality rule, because Anthropic's human testers caught early agents preferring SEO content farms **[V]**. For an emotional-support researcher, that rule means preferring clinical, academic and counselling-body sources over wellness blogs. The robot path needs no new pattern. The I2 crisis checker already runs in parallel with the helper, with a veto held at I3b. That is parallel-with-veto, not parallel decision-making, and it fits both sources. LangGraph supervisor's `forward_message` idea, passing a worker's text through verbatim, only needs a check that I3b does not paraphrase.

Two memory designs from the literature fit the note-taker (I5) if the robot lane has time. Generative Agents ranks memories by the sum of min-max-normalised recency (decay **0.995** per hour), LLM-rated importance (1–10) and embedding relevance, with all weights set to 1. It reflects when recent importance sums past **150**, writing insights that cite evidence ("because of 1, 5, 3"). In its ablation, removing reflection dropped TrueSkill from **29.89 to 26.88** **[V]** ([arXiv 2304.03442](https://ar5iv.labs.arxiv.org/html/2304.03442)). The researchers did not check whether past.dev already ranks results this way, so check before building. MetaClaw's consolidator merges near-duplicates at Jaccard ≥ 0.80 within a memory type, keeps a `superseded_by` chain instead of deleting, and sets per-type TTLs (30 days episodic, 365 preference) **[V]**. The supersede chain and the TTL fit the existing follow-up-expiry design. Its auto-resolution of conflicts, where the older fact is superseded, is risky for emotional-support facts ("my sister is supportive" → "we fell out"). Those conflicts should go to the confirm step instead (inference).

MetaClaw-Bench is the most demo-friendly design here for the robot and memory story. It uses no LLM user. Each of 30 days has a seeded session and scripted rounds, scored by **deterministic checkers** such as a regex for ISO-8601 timestamps. Hidden preferences are introduced on a "first introduction" day and re-tested later. Scripted corrective feedback is prepended to the next question, and the result is a per-day accuracy curve **[V]** ([MetaClaw repo](https://github.com/aiming-lab/MetaClaw), `benchmark/data/metaclaw-bench/`). The puddles adaptation is a hybrid: scripted rule probes plus the existing LLM simulated user for open turns. For example, "call me Sam" is introduced on day 1 and checked by keyword on day 3, and "don't suggest therapy unless I ask" is checked by regex. The result is a reproducible memory curve that does not depend on the LLM judge.

## Conclusion

Read across these systems, the self-improving part is commodity. Every one of them has a mutate step. What separates a credible result from a lucky one is the machinery *around* the mutation: who may write what, how noise is measured, which variant the next step builds on, and whether the evidence sits outside the thing being changed. DGM's most-cited lesson is the hack it caught through lineage, not its 20% → 50% gain. SICA's best idea lives in a code function its paper never describes. For puddles this means the novelty claim (a proposer that chooses between harness, weights and no-op from a scoreboard) is only as strong as the gate, archive and logs that show what each choice did.

One shift matters for the next 19 hours. The repos show that the cheapest additions, a hashed contract, staged evaluation, a CI-based parent rule and a parent-pointer archive, also make the overnight run faster and more autonomous, so rigour and results do not compete for time. The reporting items (level labels, prediction calibration, safety trajectory, backward transfer) need almost no new compute. They turn the existing decision log into exactly the evidence that the 2026 surveys say the field is missing.
